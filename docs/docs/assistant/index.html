Documentation/Core workflows

AI Assistant

Describe your goal and let the assistant check environments, install tools, or perform real tasks.

Prepare a working model before starting

  1. Open AI Assistant. In normal conversation mode, first choose a configured model that works.
  2. Confirm whether the target is this computer or an SSH server added on the right. The target determines the context for subsequent operations.
  3. Explain what you want to do, which tool is involved, and the result you expect. Include the specific error if needed.
  4. After sending, watch the working status, tool calls, and results. Expand tool cards to inspect arguments and output.

Requests that work better than “fix this for me”

  • “Check the installation and launch environment for Claude Code on this computer, and tell me what problems you find first.”
  • “Help me install Git, then check that it is available in the terminal.”
  • “This tool reports the following error when it starts: … Please investigate the cause and explain what you fixed.”
  • “Inspect this computer’s hardware and explain what kinds of local models it can run.”

The assistant chooses steps based on the model, task, and environment. Finding a route, installing a runtime, and configuring PATH in the website animation are examples, not a mandatory pipeline for every task.

Confirm what the assistant actually did

AI Assistant can run real commands and operate on files. Tool output can tell you more than the final summary about whether installation finished, which files changed, or whether an error was resolved. After installation, return to App Desktop, refresh detection, and launch the tool to verify it.

You can stop a running task, but stopping does not undo commands already executed. Not every task prompts for confirmation at every step. Define the goal and permitted scope first, and do not casually paste unknown commands or credentials into the assistant.

Conversations and settings for each turn

Create, switch, and delete conversations to keep projects or tasks separate. Deleting a conversation requires confirmation, but does not uninstall tools that were installed during it. Settings such as the model and reasoning effort are generally determined when you send a message. A running task uses the settings submitted for that turn; later adjustments mainly affect the next turn.

Connect to an existing agent

Connect mode currently supports an installed Claude Code CLI. In this mode, Claude Code handles the turn using its own environment, tools, memory, and model configuration. EchoBird hides its model selector.

To change that model, manage it in App Desktop or Claude Code’s own settings. Do not assume that model selection in normal assistant mode applies to Connect mode.

Run tasks on your own server

Add an SSH server on the right by entering its host, port, username, and authentication details. Test the connection before selecting it for a task. The remote machine must already have an accessible SSH service; this feature does not purchase or create a cloud server for you.

Deleting a server removes only its saved connection entry, not software on the remote machine. Follow the actual prompts when system privileges are needed. Local steps that require a password may be handed over to a native terminal.
