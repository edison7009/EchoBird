组合使用教程

把独立页面连成真正可用的工作流，理解每一步带来的效果。

路线一：沿用现有订阅

  1. 应用桌面：识别或安装你习惯的客户端。
  2. 账号中心：添加官方账号，核对身份与授权。
  3. 应用桌面：选择客户端、选择账号，再执行应用与启动。
  4. 真实客户端：检查身份并发起请求；需要时回账号中心刷新额度。

得到的效果：账号状态集中管理，工具仍按熟悉的方式使用。添加账号和切换客户端有明确分工。

路线二：多个工具，复用模型

  1. 模型中心：保存服务地址、Key 和模型 ID，点击「测试速度」检查连接与延迟。
  2. 应用桌面：为支持的工具选择这条模型并应用配置。
  3. 第二个工具：复用同一模型条目，按它支持的协议应用。
  4. 验证：分别在工具里请求，确认不是只在 EchoBird 保存了配置。

得到的效果：减少重复输入，保留清楚的模型来源。协议和能力仍以每个工具及模型的支持情况为准。

路线三：常用模型与备用线路

  1. 在模型中心验证首选和备用 API，也可以准备受支持的账号来源。
  2. 在智能接入创建方案，设置实际入口与密钥，按优先级安排来源。
  3. 把编程客户端接入该方案，发起真实请求。
  4. 在统计中观察完成与切换结果；把常用用量加入用量岛。

得到的效果：客户端连接相对稳定，来源可以集中调整。看到额度或失败变化时，有状态信息可帮助判断下一步，而不是盲目重复请求。

路线四：从报错到继续工作

  1. 在应用桌面确认安装状态，保留无法启动时的具体错误。
  2. 进入 AI 助手，说明工具名、系统、错误和期望结果。
  3. 观察环境检查和工具输出，必要时按系统提示处理权限。
  4. 回应用桌面刷新检测并实际启动，再确认问题已经解决。

得到的效果：把安装排障和实际验收连起来。助手的总结帮助理解过程，真实启动结果用来确认效果。

路线五：口述需求，保持专注

先在语音输入配置通道并测试麦克风，再把光标放到 AI 助手或你常用的工具里。口述任务、检查识别文字、发送。工作时用用量岛观察状态；经过智能接入记录的 Token，也可以在宠物页转为成长体验。

路线六：自己的硬件，自己的模型服务

本地大模型准备文件与引擎并启动服务，再让支持的模型入口和 AI 助手使用它。遇到问题先分清是服务没启动、模型不可用，还是任务本身失败。这样能把「运行模型」和「让模型做事」分别验证。
