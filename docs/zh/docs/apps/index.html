使用文档/核心工作流

应用桌面与商店

发现工具、安装工具、选择来源，再完成应用配置与启动。

「我的」：把熟悉的工具放在一起

应用桌面展示常用 AI 客户端、CLI 与相关工具。选中图标后，右侧展示这个工具可用的账号与模型配置。工具本身仍是你熟悉的客户端，EchoBird 负责集中管理入口与受支持的配置。

不是每个工具都支持相同操作。有的能切换官方账号，有的能填写 API 模型，有的主要提供启动入口。先看当前工具实际显示的选项。

已安装却没被识别

  1. 确认第三方工具已经完成安装，能在系统里正常启动。
  2. 回到 EchoBird 点击刷新，让它重新检测本机工具。
  3. 如果仍未识别，打开工具路径配置入口，核对工具可执行文件的位置。
  4. 修正后再次刷新。不要把其他项目的启动文件当成这个工具，也不要为了检测成功随意覆盖原有账号配置。

「商店」：从发现到安装

商店提供未安装工具的分类与入口。选择工具后使用「一键安装」，会进入 AI 助手并预填该工具的安装请求。之后要结合助手输出和你的系统环境继续完成安装。

安装并非浏览时自动发生

浏览商店或选中图标不会自动安装软件。安装可能涉及下载、依赖、网络与系统权限；助手完成后，回到应用桌面刷新并实际启动工具，才能确认结果。

账号和模型怎样真正用到工具上

  1. 选中已安装工具，再选官方账号或 API 模型。两种来源互斥，避免客户端使用冲突的身份和接口。
  2. 查看底部是否需要写入配置、是否同时启动。只想配置时按当前工具允许的选项执行。
  3. 执行主操作并等待结果。若涉及运行中的客户端或恢复官方接口，以客户端提示处理。
  4. 打开对应客户端检查实际身份和模型。右侧高亮表示当前选择，不保证所有已经运行的窗口立即完成切换。

Web Search、Image 与 1M

能力项含义需要知道
Web Search支持工具的联网搜索配置还取决于模型和服务端能力
Image支持工具的图像输入配置开启按钮不会让纯文本模型自动获得视觉能力
1M支持工具的大上下文模式实际上下文、费用与限制由工具及服务决定

药丸按钮彼此独立，可以分别启用。真实客户端中，部分工具在已有有效 API 配置时会重新应用能力设置；它们并非始终只改变外观。没有出现某个按钮时，以当前工具开放的能力为准。

推荐用法

先保留一个工作正常的官方账号或模型配置，再为常用工具建立清晰的选择习惯。需要多来源与故障切换时，把工具接到智能接入，而不是每次进入客户端重复改接口地址。
